# 智能网文小说创作工作台

> 长篇网文的一站式生产流水线：**规划 → 生产 → 质检 → 纪律**。题材与文风**不设限**——仓库内以一部穿越权谋长篇作为**示例**，题材锚定、主角卡、文风模板都只是可替换的参考样本，按自己的题材与风格改写即可。
> 除流水线与脚本外，仓库还含一个可在浏览器直接阅读全文的 **Web 阅读器**，以及示例作品的 **259 章源稿**。

## 这是什么

把长篇网文的生产拆成可复用的流水线段，配套确定性机检（格式 / 字数 / 引号 / 违禁词 / 跨章重复）与全维审校（八个维度逐项过筛），解决「写作进度与审检进度不同步」的老问题。产物既有结构化的规划文档，也有可直接发布的 Web 阅读器数据。

## 样本正文（novel-source/）

仓库附一部穿越权谋长篇的 **259 章原始 markdown**，仅作**样例**，用于展示流水线的产物格式与文风落地方式（数字章节名、局点标注、单章字数区间等）。**你的项目不必是这个题材，也无需沿用这里的风格**：

- 卷一 110 章 / 卷二 110 章 / 卷三 39 章，合计约 **69.9 万字**
- 想换成自己的书：把 `novel-source/` 整体替换为你的章节文件（`NNN_章名.md`，放在任意卷目录下即可），再跑一次 `web/build.py`。脚本找不到外部精修稿目录时会自动回退读 `novel-source/`
- 规划层文档（`projects/`）与文风模板（`01`–`06`）同样只是样板，按需改写

> 示例正文版权归作者所有，许可范围见文末「许可证」。

## 目录结构

```
.
├─ web/                 # Web 阅读器 + 构建
│  ├─ index.html        # 单页阅读器（总览 / 阅读 / 搜索 / 编辑）
│  ├─ data.js           # 由 build.py 打包的成品数据
│  ├─ build.py          # 扫描正文 md → 生成 data.js
│  ├─ server.py         # 本地服务（支持在线写回 .md）
│  └─ serve_threaded.py
├─ novel-source/        # 示例作品 259 章 markdown（可整体替换）
│  ├─ 卷一_龙潜于渊/
│  ├─ 卷二_定鼎新朝/
│  └─ 卷三_宏图初展/
├─ projects/            # 规划层文档样板（总纲 / 人物库 / 时间线 / 大纲 / 伏笔 …）
├─ benchmark/           # 对标基准包（文风向量、拆解实例）
├─ 00-06*.md            # 流水线各阶段说明（题材 / 人物卡 / 文风 / 伏笔 / 质检 / 对标）
├─ qc_audit.py          # 确定性机检脚本
├─ check_quotes.py      # 引号规范批检
└─ batch_clean.py       # 批量清洗（引号 / 空白）
```

> 正文源优先级：`NOVEL_PROJECT_ROOT/正文_精修版` → 工作台同级目录/穿越之我是杨广/正文_精修版 → 仓库自带 `novel-source/`。用环境变量 `NOVEL_PROJECT_ROOT` 可指向你自己的项目根，无需改代码。

## 快速开始

**仅浏览（零依赖）**：直接打开 `web/index.html`，或起本地静态服务——
```bash
python3 -m http.server 8000 --directory web
```

**重新构建 data.js**（扫描正文 md 打包）——
```bash
python3 web/build.py
```
构建完成后若存在 `docs/`，会自动把 `data.js` 与 `index.html` 同步过去（GitHub Pages 只发布 `docs/`），不必手工拷。

**本地服务（支持在线编辑写回 .md）**——
```bash
python3 web/server.py    # 浏览器访问 http://127.0.0.1:8770
```

**确定性质控机检**——
```bash
python3 qc_audit.py
python3 qc_audit.py --root ../我的项目      # 指定项目根（默认=脚本所在目录，无正文时回退 novel-source/）
```
机检会写 `_工单与报告/机检报告/机检审校报告.md` 与状态文件；`--deep-seeded N` 用于声明已完成全维审校的章数，不传则沿用状态文件里的进度。
