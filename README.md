# 智能网文小说创作工作台

> 长篇网文的一站式生产流水线：**规划 → 生产 → 质检 → 纪律**。题材与文风**不设限**——仓库内以一部穿越权谋长篇作为**示例**，题材锚定、主角卡、文风模板都只是可替换的参考样本，按自己的题材与风格改写即可。
> 除流水线与脚本外，仓库还含一个可在浏览器直接阅读正文的 **Web 阅读器**，以及示例作品的 **前 10 章样章**（全稿不入库）。

**作者**：tiger5325（[@tiger5325](https://github.com/tiger5325)）

## 🔗 在线预览

- **GitHub Pages 阅读器**：https://tiger5325.github.io/novel-workbench/
- Pages 版为**只读浏览**；在线编辑 / 保存（`/api/save`）依赖本地 Python 服务，见「快速开始」。

## 这是什么

把长篇网文的生产拆成可复用的流水线段，配套确定性机检（格式 / 字数 / 引号 / 违禁词 / 跨章重复）与全维审校（八个维度逐项过筛），解决「写作进度与审检进度不同步」的老问题。产物既有结构化的规划文档，也有可直接发布的 Web 阅读器数据。

## 样本正文（novel-source/）

仓库附一部穿越权谋长篇的**前 10 章原始 markdown**（卷一第 001–010 章，约 2.6 万字），仅作**样例**，用于展示流水线的产物格式与文风落地方式（数字章节名、局点标注、单章字数区间等）。作者的全稿（259 章 / 约 69.9 万字）不随仓库发布。**你的项目不必是这个题材，也无需沿用这里的风格**：

- 样章覆盖卷一的第 001–010 章，够看清「一章长什么样」；全稿结构与进度见下方「当前进度」
- **规划层不入库**：`projects/` 只留一份《00_规划层说明》，说明 11 份规划文档各写什么、按什么顺序写；示例作品的总纲、人物库、时间线、十卷提纲、谋略库等**均不随仓库发布**，请按说明自建
- 想换成自己的书：把 `novel-source/` 整体替换为你的章节文件（`NNN_章名.md`，放在任意卷目录下即可），再跑一次 `web/build.py`。脚本找不到外部精修稿目录时会自动回退读 `novel-source/`
- 文风模板（`01`–`06`）是带占位符的通用模板，可直接改用

> 样章正文版权归作者所有，许可范围见文末「许可证」。

## 目录结构

```
.
├─ web/                 # Web 阅读器 + 构建
│  ├─ index.html        # 单页阅读器（总览 / 阅读 / 搜索 / 编辑）
│  ├─ brand.json        # 书名 / 卷名 / 导航卡片（换书只改这里）
│  ├─ data.js           # 由 build.py 打包的成品数据（生成物，不入库）
│  ├─ build.py          # 扫描正文 md → 生成 data.js（docs/ 另出样章版）
│  ├─ server.py         # 本地服务（支持在线写回 .md）
│  └─ serve_threaded.py # 纯静态服务（多线程，只读）
├─ docs/                # GitHub Pages 发布目录（构建时自动同步，正文限前 10 章样章）
├─ novel-source/        # 示例作品前 10 章 markdown（可整体替换）
│  └─ 卷一_龙潜于渊/
├─ projects/            # 规划层（仅《00_规划层说明》，示例作品规划不入库）
├─ benchmark/           # 对标基准包（文风向量、拆解实例）
├─ 00-06*.md            # 流水线各阶段说明（题材 / 人物卡 / 文风 / 伏笔 / 质检 / 对标）
├─ qc_audit.py          # 确定性机检脚本
├─ qc_rules.json        # 机检规则（字数区间 / 词表 / 套话表 / 文风带，换书只改这里）
├─ check_quotes.py      # 引号规范批检（直接跑，扫 novel-source/）
└─ batch_clean.py       # 格式清洗（默认预览，--apply 才落盘）
```

> 正文源优先级：`NOVEL_PROJECT_ROOT`（环境变量）→ 工作台自身或同级目录中带 `正文_精修版/` 的目录 → 仓库自带 `novel-source/`。构建与机检共用同一套解析逻辑，克隆后不改代码即可跑通。
>
> `data.js` 有两份落点，**内容按用途分流**：`web/data.js` 供本地阅读器，含全部正文，属生成物（已 `.gitignore`，克隆后跑一次 `build.py` 即可得到）；`docs/data.js` 是 Pages 的发布快照，正文**只保留前 10 章样章**（`SAMPLE_MAX_CH` 控制，环境变量 `NOVEL_SAMPLE_MAX` 可覆盖，设 0 即全量）。两份都做了「内容没变则沿用上次时间戳」，不会产生「只改了时间」的空 diff。

## 快速开始

**第一步：生成 `data.js`**（阅读器的一切数据都来自它，仓库不预置）——
```bash
python3 web/build.py
```
构建完成后若存在 `docs/`，会自动把 `index.html` 与样章版 `data.js` 同步过去（GitHub Pages 只发布 `docs/`），不必手工拷。

**仅浏览（零依赖）**：直接打开 `web/index.html`，或起本地静态服务——
```bash
python3 -m http.server 8000 --directory web
```

**改了正文 / 文档后**：再跑一次 `python3 web/build.py` 即可。

**本地服务（支持在线编辑写回 .md）**——
```bash
python3 web/server.py    # 浏览器访问 http://127.0.0.1:8770
```

**确定性质控机检**——
```bash
python3 qc_audit.py
python3 qc_audit.py --root ../我的项目      # 指定项目根（只扫该目录，不向上探测）
python3 qc_audit.py --rules my_qc_rules.json  # 换一套规则文件
```
机检会写 `_工单与报告/机检报告/机检审校报告.md` 与状态文件；`--deep-seeded N` 用于声明已完成全维审校的章数，不传则沿用状态文件里的进度。

**引号体检 / 格式清洗**——
```bash
python3 check_quotes.py                    # 扫 novel-source/，列出问题位置
python3 batch_clean.py                      # 预览要改什么（不写盘）
python3 batch_clean.py --apply               # 真改，每个文件先存 .bak
```

## 换成你自己的书

只改三个地方，脚本一行都不用动：

| 想改什么 | 改哪里 |
|---|---|
| 书名 / 卷名 / 首页文案 / 导航卡片 | `web/brand.json` |
| 字数区间、违禁词、套话表、文风参考带 | `qc_rules.json` |
| 正文 | 替换 `novel-source/` 里的章节文件（`NNN_章名.md`，任意卷目录名） |

改完跑 `python3 web/build.py`，`data.js` 与 `docs/` 一起更新。
